# FreeRouter

> 把各大厂 AI Agent 自带的那份免费额度聚成一个池子，让用不完的人不再浪费、不够用的人有处可借。

`Free` 是个双关：**自由**——路由策略自己定，额度怎么分、谁能用哪个模型由你决定，不被单一供应商锁定；
**免费**——上游不花钱，接的是各大厂 Agent 官方免费额度的反代，而不是买 API 额度转卖。

## 它解决什么问题

**第一，额度是碎的。** 各大厂 AI Agent 几乎都在给免费额度——DeepSeek、TRAE、Qoder、
CodeArts、Gemini、Cline、ModelScope……每个背后都是一个账号、一套登录方式、一套限流、
一个到期时间。想用的时候得先想「今天该开哪个」，用完还得回头查「哪个快到期了」。

**第二，最真实的问题不是没有额度，而是额度配错人。** 免费额度是**人均一份、大致等量**的，
但消耗极不均——重度用户早就用干、轻度用户月底看着额度作废。真正稀缺的不是额度本身，
而是额度在人与人之间的重新分配。这件事个人做不到：额度绑在个人账号上，没有可以中转的中间层。

**第三，不分享才更危险。** 有人额度用不完，有人不够用，现实里的解法往往是“把账号借你用”
——直接交出 Key，意味着没有限额、没有日志、没有吊销手段，出事只能改密码。

FreeRouter 就是在额度与人之间加的一层：**下面反向代理各大厂 Agent 的官方免费额度，
上面按人和 Key 发出去**，中间做模型抽象、策略路由、额度计量与审计。

共享免费额度是**初衷与主干**；中转站该有的其他能力（多协议、抽象模型、配额、审计）
是在这条主干上顺手补齐的配套，不是目的本身。

## 核心概念

| 概念 | 一句话 |
|---|---|
| **账户** | 一个登录身份。由**显示名 + 账户 ID + 权限类集合**组成 |
| **权限类** | `admin`（只管理）/ `tenant`（只调模型）/ `contributor`（只贡献凭据）。**一个账户可同时拥有多个** |
| **隔离** | 隔离发生在**权限类之间**：能力不互授、资源分表归属、凭据不可自选、审计分账 |
| **组** | 管理员定义的批量控制单元。一个账户属多组时：**放开类取并集，限制类取最严** |
| **真实模型** | 上游池子里的模型（如 `dsh:deepseek-official/deepseek-flash`）。**只有管理员可见** |
| **抽象模型** | 管理员定义的对外模型（如 `smart` / `fast`）。**只有租户可见** |
| **候选** | 抽象模型的一个来源：真实模型 × 渠道范围 × 约束。**声明式，不绑凭据** |
| **策略引擎** | 三段式：**过滤 → 排序 → 切换**。排序默认「最快作废的额度优先用」 |
| **凭据** | 上游访问凭据。**只归属带 `contributor` 类的账户** |
| **API Key** | 租户调模型用的站点密钥。**只归属带 `tenant` 类的账户** |

## 特性

**额度池（主干）**

- **反代各大厂 Agent 的免费额度**：接的是官方客户端协议（不是买来的 API 额度），入站协议与官方一致
- **池化**：一份额度不再千人一份各自作废——用不完的余额可以被池子里的人用掉
- **耗尽感知**：按时长、按剩余量、按冷却状态排序，快过期的先花，子已干的不再派
- **额度可查**：每个上游账号的余额、到期、签到状态一目了然

> 下面几组能力都是为了让这份共享额度能被安全、稳定地发出去，属于**配套**而非目的。

**接入侧**

- 多协议入站：OpenAI Chat Completions、OpenAI Responses、Anthropic Messages、Gemini generateContent
- 对外**只暴露抽象模型**——请求真实模型名一律 404，不泄露池子结构
- 用户侧日志只出现抽象模型名；真实目标与贡献者归因仅在管理端可见

**路由侧**

- 抽象模型的能力声明取候选的**保守下界**（宁可少声称，也不要中途失败）
- 策略链：`expiry-first`（默认，免费额度场景的核心策略）/ `quota-aware` / `fastest` / `weighted` / `round-robin` / `quality-tier`
- 候选**串行尝试**而非并发竞速——并发会在多个上游同时产生真实额度消耗
- 候选切换只发生在**尚未吐出任何可见内容**之前；内容审核拒绝**绝不**换候选

**模型治理**

- **弃用与替代链**：`old → mid → new` 可多跳，客户端一个字不用改
- 弃用对外发标准响应头：RFC 9745 `Deprecation` + RFC 8594 `Sunset` + `Link: rel="deprecation"`
- 替代目标的能力必须**逐项 ≥** 原模型，否则拒绝保存

**账号与配额**

- 账户 = 权限类集合；管理面**类级提权**（进管理页当场再验一次）
- 组 = 一组策略 + 一批成员，成员之间互不可见
- 每个租户可建多个 API Key，每个 Key 独立配额、独立模型白名单、独立吊销
- 三维限速（IP / Key / 全局）+ 额度护栏

**贡献侧**

- 任何人可贡献上游账号或 API Key，未登录也能贡献（贡献即建账户，当场给恢复路径）
- 凭据加密入库，**管理员也看不到明文**；贡献者可一键撤销
- **模型鉴定**：验证「贡献的凭据声称的模型是否真的匹配」（详见 `models/05-verification.md`）
- 冷门模型无参考指纹时**默认放行**并标记「未鉴定」，进入复检队列

## 架构

```
        客户端（OpenAI / Anthropic / Gemini 协议）
                        │
                        ▼
        ┌───────────────────────────────────────┐
        │ L1 入站                                │
        │   鉴权 → 限速 → 配额 → 授权 → 模型解析  │
        ├───────────────────────────────────────┤
        │ L2 内核                                │
        │   IR ⇄ 四协议   ·   抽象模型 → 候选     │
        │   过滤 → 排序 → 切换（串行尝试）        │
        ├───────────────────────────────────────┤
        │ L3 上游                                │
        │   dshgateway      │    contributed     │
        └───────────────────────────────────────┘
                 │                      │
                 ▼                      ▼
        127.0.0.1:8326            各供应商官方端点
     （dsh-providers-hub）      （贡献者提供的凭据）
```

- **L1** 只做准入，不碰模型语义。
- **L2** 是唯一知道「抽象模型 → 真实模型」映射的地方，也是唯一做协议转换的地方。
- **L3** 把「上游」抽象成统一的 `Upstream` 记录——供应商账号与普通 API Key 在这里**地位完全等价**，
  差别只体现在「怎么取凭据」与「怎么查额度」两个函数里。绝大多数上游是**各大厂 Agent 官方
  免费额度的反代**：先按官方登录流拿到账号凭据，再用它向官方端点发请求。

进程形态：**Go 主服务 + Node sidecar**。sidecar 内嵌
[dsh-providers-hub](https://github.com/iJetLi/dsh-providers-hub)，复用它对 17 家供应商的登录流与凭据续期；
两者之间走本机 Unix socket，sidecar 不监听任何网络端口。

## 与相邻项目的关系

| 项目 | 关系 |
|---|---|
| [Tingly Box](https://github.com/tingly-dev/tingly-box) | **同类参考**。它是一个功能更全的 AI 网关（自带智能应用接入向导、团队共享端点、IM 远程控制）。FreeRouter 有意**不做**这三块，换来更简单的权限模型与更窄的攻击面 |
| dsh-providers-hub | **上游额度来源**。它管着「免费额度从哪来」（多账号池、静默续期、积分领取/签到、临期排序），FreeRouter 管「额度怎么发出去」（抽象模型、策略路由、租户配额、审计） |

## 项目状态

**实现阶段：M0–M9 主体落地，M10 加固进行中。**

后端（Go）、sidecar（Node）与控制台（React + MUI v9）都已有可运行实现；前端构建产物经
`webui_dist` 构建标签嵌入单二进制。里程碑的逐项推进与验证记录在 [CHANGELOG.md](CHANGELOG.md)
（M10 实跑结论也在其中）。当前质量基线见
[ops/05-static-analysis.md](docs/ops/05-static-analysis.md)：`gofmt` / `go vet` / `staticcheck`
零告警，`gosec` 的告警已逐条评估，单元与契约测试全绿。

尚未拍板的设计点汇总在 [`docs/OPEN-QUESTIONS.md`](docs/OPEN-QUESTIONS.md)（205 条，按阻塞级分 A/B/C）。

### 快速开始

```bash
make web        # 构建前端到 internal/webui/dist（嵌入单二进制的前置）
make release    # 完整单二进制 bin/freerouter（内嵌前端，日常运行用这个）
make build      # 纯 Go 快速编译（不含前端，控制台是占位页）
make test       # 单元测试；make contract 只跑契约测试，make test-race 带竞态检测
make vet        # go vet；make fmt 格式化；make tidy 整理依赖
make run        # 用 testdata/config.yaml 前台启动
```

构建缓存固定在仓库内（`.cache/`，不入库）：本机 `~/.cache` 与 `~/go` 在沙箱下只读，
Makefile 已把 `GOMODCACHE` / `GOCACHE` / `GOPATH` 指到工作区，无需额外环境变量。

## 免责声明

FreeRouter 的核心用法是把各大厂 Agent 的个人免费额度**共享**给别人用，
这**可能违反部分供应商的服务条款**，也可能触发风控。请在使用前自行确认
你的使用方式是否符合各供应商的约定——本项目只提供技术手段，不提供合规判断。
