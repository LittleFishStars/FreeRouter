# 公网安全基线

本册是**上线前必须逐条勾选**的清单。FreeRouter 是公网暴露的多用户中转站，
上游额度是真实的账号——**没有这些措施就等于把账号送出去**。

**为什么这份清单是硬性的**：与内网工具不同，公网暴露意味着任何人（包括
自动化扫描器）都能到达我们的鉴权面。上游额度一旦被白嫖，损失记在账号主头上，
且可能触发上游风控导致账号被封，影响的是**所有**使用该渠道的租户。

---

## 1. 威胁模型

### 1.1 要防的四类事

| # | 威胁 | 后果 | 主要对策章节 |
|---|---|---|---|
| T1 | **Key 泄露 → 白嫖上游额度** | 额度损失 + 上游风控 | §4 §5 |
| T2 | **账户被盗 → 拿到 Key 或管理权** | 同 T1，管理权失守更严重 | §3 §6 |
| T3 | **贡献凭据被我们泄露** | 极严重，破坏众包信任基础 | §4 |
| T4 | **滥用（刷量、爬取、转售）** | 额度耗尽、上游告警 | §5 §7 |

### 1.2 设计原则

1. **默认拒绝**：账户注册即 `pending`；新建 Key 默认额度 0、白名单为空。
2. **显式授权**：任何能力都要有人明确授予（权限类、组、Key 白名单）。
3. **额度护栏先行**：限速与配额在**功能之前**实现——没有护栏的出口不能上线。
4. **最小可见**：凭据明文任何人不可见（含贡献者本人）；租户看不到真实模型名。

**为什么强调「默认拒绝」**：几乎所有中转站的泄露事故都来自「功能先上、
护栏后补」，而护栏后补时已经有真实流量在白嫖。反过来做没有额外成本。

### 1.3 不在防御范围（要清楚）

- 上游供应商自身的风控判决——我们只能降低触发概率，不能保证不被封。
- 贡献者自己把上游账号密码泄露到别处——我们只能保证自己这一侧不泄露。
- 租户把 Key 主动发给别人——无法技术阻止，靠额度上限兜底。

不假装能防住。写清楚边界，避免上线后误判责任。

## 2. 传输与边界

- [ ] **强制 HTTPS**：内置 ACME（autocert）或反代终止，二者选一。
- [ ] **不允许明文对外**：检测到公网监听且无 TLS 时**拒绝启动**并打印明确原因。
- [ ] 只暴露 **443**（+ 80 供 ACME 挑战）；**管理面不单开端口**，走同一端口不同路径。
- [ ] `TRUSTED_PROXIES` 显式配置；**未配置时忽略 `X-Forwarded-For`**。
- [ ] 安全响应头：HSTS、CSP、`X-Content-Type-Options: nosniff`、
      `Referrer-Policy: same-origin`、`X-Frame-Options: DENY`。
- [ ] CORS 默认关闭（同源）；跨域需显式白名单，**禁止 `Access-Control-Allow-Origin: *`
      与凭据同时出现**。
- [ ] 入站请求体上限默认 **32 MiB**，超限返回 413（早于上游的 300 MiB 限制）。
- [ ] 服务器 banner 不泄露版本号。

**为什么 `TRUSTED_PROXIES` 是硬项**：IP 限速是防刷的第一层，而 `X-Forwarded-For`
是客户端可任意伪造的头。如果无条件信任它，攻击者每次请求换一个假 IP，
IP 限速就完全失效——**看起来有防护，实际没有**，比不做更危险。

**为什么入站上限要小于上游的 300 MiB**：上游给 300 MiB 是因为它面向
「单条消息允许 200 MiB 原图、base64 膨胀 4/3」的客户端；我们面对的是公网，
更大的 body 意味着更大的内存与 DoS 面。提前拒绝比传完再拒更省资源。

## 3. 账户与认证

- [ ] 密码 **≥12 字符**，argon2id（参数：内存 ≥64 MiB、迭代 ≥3、并行度 = CPU 数）。
- [ ] **防枚举**：注册与登录对「已存在 / 不存在」的**响应时间恒定**且**文案一致**。
- [ ] **登录防爆破**：失败计数 + 指数退避 + 锁定窗口；失败记录含 IP / UA 进审计。
- [ ] **类级提权**：进入管理面或改配置时当场再验（TOTP 或重输密码）；
      提权有效期 15 分钟；危险操作**每次**重验。
- [ ] **禁用联动**：账户转 `disabled` → 名下所有 Key **立即** 401、会话立即吊销。
      鉴权层**实时查账户状态**，不依赖可能有延迟的缓存。
- [ ] 会话 Cookie：`HttpOnly` + `Secure` + `SameSite=Lax`；登录成功后轮换 session id。
- [ ] 改密 / 禁用即吊销该账户全部会话。
- [ ] 可选：管理面来源 IP 允许列表。
- [ ] **OAuth 登录的会话默认低权限上下文**，要进管理面必须另外提权。

**为什么「禁用联动」必须实时**：缓存 30 秒看似无害，但被封禁的账户在
这 30 秒内可以继续消耗上游额度。禁用是应急手段，**应急手段不能有延迟**。

**为什么危险操作每次重验**：提权有效期 15 分钟是给「连续配置」留的体验空间，
但删账户、改组、改抽象模型、改弃用这类操作**不可逆或影响全站**，
一旦会话被劫持就会造成不可恢复的后果。用一次性确认把窗口压到最小。

## 4. 密钥与凭据

### 4.1 API Key

- [ ] 格式 `fr-` + 32 字节随机（base62）；**只存 SHA-256**，明文仅创建时返回一次。
- [ ] 列表只显示前缀 + 后 4 位（`fr-xxxx…xxxx`）。
- [ ] 比较用 `crypto/subtle.ConstantTimeCompare`（防时序侧信道）。
- [ ] 支持即时吊销；吊销后**立即**生效（同样不依赖缓存）。
- [ ] 允许设置过期时间。

### 4.2 上游凭据

- [ ] 落库前用 **AES-GCM** 加密；主密钥来自环境变量或 `0600` 文件，**永不入库**。
- [ ] **凭据明文永不回显**——包括贡献者本人、包括管理端。
- [ ] 数据库文件权限 `0600`，且不在 Web 可访问路径下。
- [ ] 凭据使用记录（何时被哪个请求用过）只记**凭据 ID**，不记内容。
- [ ] 贡献者可一键撤销；撤销后该凭据立即退出候选池。

**为什么主密钥不入库**：密钥与密文放在同一处等于没加密——拿到数据库文件的人
同时也拿到了解密能力。分开存放使得「拖库」与「解密」成为两次独立事件。

**为什么贡献者本人也不可见**：凭据明文一旦能回显，它就必然会出现在
截图、日志、工单、浏览器历史里。**能看见就会泄露**，这是一条经验规律而非过度设计。

---

## 5. 限速、配额与护栏

- [ ] **三维令牌桶**：全局 / 按 Key / 按 IP；超限返回 `429` + `Retry-After`。
- [ ] 每个 Key 强制 **日 / 月 token 上限**与**并发上限**，有全局默认值兜底。
- [ ] **全局预算熔断**：全站当日用量超标自动拒绝并告警。
- [ ] **异常用量检测**：单 Key 单位时间用量突增 → 告警（可选自动暂停）。
- [ ] 账户级上限：Key 数量、每人日/月额度（由组的限制类策略取最严得出）。
- [ ] 注册速率限制（按 IP），可选邀请码。

**为什么是三维而不是单维**：只有按 Key 限速时，攻击者可以刷注册拿新 Key；
只有按 IP 限速时，同一 IP 的多租户会互相影响。三维各自堵一类漏洞：
IP 挡注册滥用、Key 挡租户超用、全局挡整体失控。

**为什么默认额度是 0**：新建 Key 若带默认额度，用户「先建了再说」就会产生
无授权消耗。默认 0 强制发生一次显式授权动作，把责任与可见性交给创建者。

---

## 6. 审计与可观测

- [ ] 审计日志 **append-only**：管理操作、鉴权失败、额度熔断、上游错误、
      **提权事件**、**组变更**、**凭据增删**。
- [ ] 每条审计记录含 `account_id + acting_class + elevated + ip + ua + result`。
- [ ] **默认不记录请求正文**；排查时开脱敏模式（保留结构、抹掉文本）并在 UI 明示。
- [ ] 请求日志记录：端点、抽象模型、**真实落点（仅管理端可见）**、状态码、
      TTFT、耗时、输入/输出 token、错误码。
- [ ] 指标：QPS、P50/P95 延迟、错误率、上游健康、额度消耗速率。
- [ ] 告警渠道（至少一种）：额度熔断、上游持续失败、鉴定复检失败、
      异常用量。

**为什么默认不记正文**：中转站会流经用户的代码、文档、凭据片段。
默认记录正文等于建了一个高价值泄露目标，而且一旦泄露无法挽回。
「默认不记」把风险设为 opt-in，需要时由管理员显式开启并告知。

**为什么审计要记 `acting_class`**：同一账户可能同时是管理员和租户。
不记类就无法区分「他改了配置」与「他调了模型」，
事后追责时会把两种行为混为一谈。

---

## 7. 运行态加固

- [ ] 容器**非 root** 运行；`--read-only` 根文件系统 + 仅数据目录可写；
      `--cap-drop=ALL`。
- [ ] `/healthz`（进程存活）与 `/readyz`（含上游连通性）**分离**。
- [ ] 结构化日志（`slog` JSON）+ 日志轮转，不无限增长。
- [ ] CI 跑 `govulncheck ./...`，无高危才允许发布。
- [ ] 依赖版本锁定（`go.sum`）；定期更新。
- [ ] 优雅关闭：收到信号后停止接受新连接、drain 进行中的流式请求。
- [ ] 数据库备份见 [02-deploy.md](02-deploy.md#备份与恢复)。

**为什么 healthz 与 readyz 要分开**：上游短暂不可用时进程是健康的，
不应该被编排系统重启（重启解决不了上游问题，反而丢失连接池与进行中的请求）。
分开之后，负载均衡可以停止导流而不杀进程。

## 8. 上线前检查清单（总表）

按顺序执行，**任一项不通过就不上线**。

| # | 检查 | 验证方式 |
|---|---|---|
| 1 | 无 TLS 时拒绝启动 | 配置里不写 TLS 证书，公网监听 → 启动应失败 |
| 2 | 伪造 `X-Forwarded-For` 不能绕过 IP 限速 | 未配 `TRUSTED_PROXIES` 时带假头打请求，限速仍生效 |
| 3 | 新建 Key 无法直接使用 | 建 Key 后不配置额度与白名单 → 请求被拒 |
| 4 | 账户 `disabled` 后名下 Key 立即 401 | 禁用账户，立刻用旧 Key 请求 |
| 5 | 未提权进不去管理页 | 管理员登录后直接访问管理路由 → 要求提权 |
| 6 | 凭据明文不可获取 | 遍历所有页面与 API，确认无回显 |
| 7 | 审计覆盖提权事件 | 提权一次，查审计是否含 `elevated=true` |
| 8 | 429 带 `Retry-After` | 打满 RPM |
| 9 | 全局熔断生效 | 调低阈值触发 |
| 10 | 容器非 root | `docker exec id` |
| 11 | `govulncheck` 无高危 | CI 输出 |
| 12 | 防枚举 | 已存在/全新用户名响应时间与文案一致 |

> **待定**：管理面是否额外限制来源 IP（总纲第 15 章第 7 项）。
> 若管理员需要从任意地点登录，则不能开这个限制；否则建议开启。
